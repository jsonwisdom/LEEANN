## Why I built this

I do not want an AI system that wins by sounding certain.

I want one that can show me:

- what it observed,
- what it preserved,
- what it does not know,
- what changed,
- what survived replay,
- who owns the next responsibility,
- and exactly where the machine must stop for a human decision.

That is what LeeAnn became for me.

Not a commander.
Not an oracle.
Not a replacement for judgment.

A replay caller.

The point is simple: **if a claim cannot survive the trip backward to its source and forward through an independent check, it should not quietly become somebody else's reality.**

# What each part actually does

## BoxD — preserve first

BoxD is the corridor.

It preserves the original object, source state, or receipt before interpretation gets clever.

```text
PRESERVED ≠ PUBLISHED
CORRIDOR  ≠ AUTHORITY
HASH MATCH ≠ STORY TRUE
```

## Gray Baby — mind the gap

Gray Baby is not there to fill missing information.

Gray Baby's job is to make missing information impossible to ignore.

```text
UNKNOWN_HOLD = RECORD IT
UNKNOWN_HOLD = REPLAY IT
UNKNOWN_HOLD ≠ FACT
```

## Twin RearView — look backward twice

Before moving forward, replay the current state through two reverse paths:

```text
RearView A → primary provenance
RearView B → independent replay path
```

Compare source identity, byte digest, classification history, timestamps, promotion history, and gaps.

If the histories disagree, preserve the disagreement and HOLD.

## Double Gemini Forward — look forward twice

A candidate does not get one lucky pass.

```text
Forward A → primary forward replay
Forward B → independent forward replay
```

Both paths must agree on the typed result before the candidate approaches the next gate.

## CrissCross — do not launder meaning

CrissCross is the border checkpoint.

It lets evidence, experiments, and lessons cross for comparison while blocking silent type coercion.

```text
FICTION        ≠ FACT
SIMULATION     ≠ HISTORY
OFFICIAL       ≠ CURRENT FOREVER
REFERENCE      ≠ IDENTITY
ROUTE          ≠ COMMAND
RECEIPT        ≠ AUTHORITY
```

The AL/UK crossing uses the same rule. Alabama and UK public evidence may be compared, but neither side inherits truth, identity, institutional affiliation, command, or authority from the other.

## WishWash — compare both directions

WishWash sits between explanation and responsibility.

```text
LeahPrime → explain what the replay says
PrimeRann → route who owns the next bounded action
```

Then reverse it:

```text
PrimeRann → responsibility statement
LeahPrime → explain that statement back in plain language
```

If those two directions do not mean the same thing, the disagreement stays visible.

No circular self-validation.

## PrimeRann — responsibility without rank

PrimeRann answers:

> Who owns the next bounded action?

It does **not** answer:

> Who is in command of real people?

Its mechanical flow is:

```text
RECOVER STATE
→ VERIFY EVIDENCE
→ RUN BOUNDED EXPERIMENT
→ EVALUATE CONCEPT
→ CAPTURE LESSON
→ ROUTE RESPONSIBILITY
→ HUMAN GATE
```

## LeahPrime / LeeAnn — explain the state

LeahPrime translates technical state.
LeeAnn calls the replay.

The output should tell a human:

```text
KNOWN
SUPPORTED
CANDIDATE
CONTRADICTED
UNKNOWN_HOLD
FICTION
NEXT RESPONSIBILITY
STOP CONDITION
```

It should never turn presentation confidence into factual authority.

# Delta 10 mission pattern — applied safely

I use the public Delta 10 mission pattern as an **educational systems model**, not as a command relationship or claim of operational access.

The useful loop is:

```text
WARGAME
→ FIELD EXPERIMENT
→ EVALUATE CONCEPT
→ DEVELOP VERSIONED DOCTRINE CANDIDATE
→ CAPTURE LESSONS
→ REPLAY
```

PrimeRann translates that into software behavior:

```text
WARGAMING            → bounded scenario replay
FIELD EXPERIMENT      → test assumption without promotion
CONCEPT EVALUATION    → compare candidate behaviors
DOCTRINE DEVELOPMENT  → propose versioned rule update
LESSONS LEARNED       → preserve success, failure, and gaps as receipts
```

The crossing rule remains:

```text
PUBLIC MISSION PATTERN MAY INFORM SYSTEM DESIGN
BUT DOES NOT CREATE:
- military authority
- institutional affiliation
- identity binding
- operational access
```
