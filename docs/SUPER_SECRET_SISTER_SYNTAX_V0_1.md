## Reverse replay

Reverse does **not** attempt to reconstruct or overwrite source bytes from an interpretation. It traverses the recorded provenance graph backward:

```text
RECEIPT
→ OUTPUT
→ DECLARED TRANSFORMS
→ ROUTE
→ GAP SNAPSHOT
→ COMPARE INPUTS
→ SOURCE STATUS
→ SOURCE REFERENCES
→ PRESERVED ORIGINAL
```

Core law:

```text
REVERSE_REPLAY = PROVENANCE_TRAVERSAL
REVERSE_REPLAY != SOURCE_REWRITE
REVERSE_REPLAY != IDENTITY_TRANSFORM
```

Forward proves the derivation was bounded. Reverse proves the claims remain sourced. Neither direction turns fiction, interpretation, doctrine, or a voice command into evidence.

## Acceptance test

A command path passes only if:

1. the target is explicit;
2. the source references remain identifiable;
3. missing or conflicted information remains visible;
4. every transform is declared;
5. the receipt can be replayed forward;
6. the receipt can be traversed backward to its source references;
7. reverse traversal does not mutate the source;
8. human review remains available before public promotion;
9. no external authority is created.
